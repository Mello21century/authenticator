Self-host and build from source

Run your own server with Docker, then point the apps at it, or build every app yourself.

What you're running

ServiceWhat it does
webnginx serving the web app, and passing /api to the API. The only service that needs a public port.
apiNestJS API: accounts, encrypted setup keys, code generation, email.
mongoMongoDB 7 with a named volume. Never exposed.

You need Docker with Compose, and for a real deployment a domain name and a Resend account for password-reset and invite emails.

Try it on your computer

git clone https://github.com/Mello21century/authenticator.git
cd authenticator
cp .env.example .env

Open .env and set the two secrets:

openssl rand -base64 48   # paste as JWT_SECRET
openssl rand -base64 32   # paste as VAULT_MASTER_KEY

Then start it:

docker network create dokploy-network   # once
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --build

Open http://localhost:8080 and create your account.

Settings

All settings are environment variables, read from .env next to docker-compose.yml.

VariableMeaning
VAULT_MASTER_KEY32 random bytes, base64. Encrypts every setup key. Losing it loses every account; changing it makes existing accounts unreadable.
JWT_SECRETAt least 32 characters. Signs sign-in sessions. Changing it signs everyone out.
RESEND_API_KEYYour Resend API key, for password-reset and invite emails.
MAIL_FROMSender, e.g. Space Authenticator <auth@your-domain>. The domain must be verified in Resend.
APP_URLPublic address of the web app, used in email links, e.g. https://auth.your-domain.
SIGNUP_ENABLEDtrue lets anyone create an account. Set false once your people have joined; owners can still invite members.
CORS_ORIGINSExtra app origins allowed to call the API, comma separated. Keep app://authenticator for the desktop app and add chrome-extension://<id> for the Chrome extension.
TRUST_PROXY_HOPSHow many reverse proxies sit in front of the API, so rate limits see the real client address. 2 behind Traefik + the bundled nginx, 1 when the web container is reached directly.

Deploy with Dokploy

  1. Create the service

    In Dokploy, create a Compose service from this repository, branch main, compose path ./docker-compose.yml.

  2. Add the environment

    Paste the variables from Settings into the service's Environment tab.

  3. Add your domain

    Domains → your domain → service web, port 80, HTTPS on with Let's Encrypt.

  4. Deploy

    Turn on auto-deploy to redeploy on every push to main.

The web service joins Dokploy's shared dokploy-network. The API is reached by the alias authenticator-api, so it can't collide with another project's service called api on the same network.

Deploy anywhere else

Any host with Docker works. Put your HTTPS reverse proxy (Caddy, Traefik, nginx) in front of the web container's port 80, publish nothing else, and set TRUST_PROXY_HOPS to the number of proxies plus one for the bundled nginx. If you don't use Dokploy, either create the dokploy-network network or remove it from docker-compose.yml.

Backups

Back up two things, and keep them apart:

  • The database: docker compose exec mongo mongodump --archive > backup.archive
  • VAULT_MASTER_KEY: in your password manager. The database is useless without it, and a stolen database is useless without it too.

Build from source

You need Node.js 24 and pnpm 11. The repository is a pnpm workspace:

apps/apiNestJS + Fastify + MongoDB
apps/webVite + React; also the desktop and Chrome UI
apps/desktopElectron
apps/extensionChrome side panel (Manifest V3)
apps/mobileExpo / React Native
packages/sharedAPI client, types, importers, design tokens
 
pnpm install
pnpm test                    # all tests; the API tests start an in-memory MongoDB
pnpm --filter api dev        # API on :3000, reads ../../.env
pnpm --filter web dev        # web app on :5173, /api proxied to :3000

Desktop apps

pnpm --filter desktop dev    # opens the app against http://localhost:8080/api
pnpm --filter desktop dist   # installers in apps/desktop/release

Packaged builds connect to https://authenticator.sz4h.com/api; set AUTH_API_URL when building to change the default. A Mac signs the build automatically if a Developer ID certificate is in its keychain. Windows installers can be built on a Mac.

Chrome extension

pnpm --filter extension build   # unpacked extension in apps/extension/dist

Load apps/extension/dist from chrome://extensions with Developer mode on. To use it with your own server, add chrome-extension://dgmbchpaamaioijdcifhfjbbpkgkdadl (the extension's fixed ID) to CORS_ORIGINS on the server, then enter the server's address under Server on the extension's sign-in screen.

Mobile apps

cd apps/mobile
EXPO_PUBLIC_API_URL=https://auth.your-domain/api npx expo run:ios       # needs Xcode
EXPO_PUBLIC_API_URL=https://auth.your-domain/api npx expo run:android   # needs Android Studio and JDK 17+

Face ID and fingerprint need a development build; they don't work in Expo Go. Store builds use EAS: npx eas-cli build -p all --profile production.

Releases

Pushing a tag such as v0.2.0 runs the release workflow on GitHub Actions: it builds the Mac DMGs, the Windows installer and the extension zips, and attaches them to a GitHub Release. Mac signing and notarization turn on when the signing secrets described in .github/workflows/release.yml are present.
